### 进程管理

[Q] 为什么子进程与父进程中变量的地址是相同的
[A] 
1. fork() 的工作原理
当一个进程调用 fork() 时，操作系统会创建一个子进程，这个子进程几乎是父进程的精确副本，包括：代码段，数据段，堆栈，文件描述符等等。关键在于，子进程获得的是父进程地址空间的一个副本
2. 虚拟内存
每个进程都拥有自己独立的私有的虚拟地址空间，因此程序中使用的地址（printf）都是虚拟地址，而不是真实的物理内存地址
3. fork() 与虚拟内存的结合
    - 复制地址空间：fork() 创建子进程是，会为子进程创建一个新的虚拟地址空间，并将父进程的虚拟地址空间的内容原封不动的复制过来
    - COW(Copy on Write)：为了提高效率，OS 不会在 fork() 时立即复制所有的物理内存，而是：1.让父子进程的虚拟地址指向同一块物理内存，并标记为只读。2.当父进程或子进程试图修改这块内存时，会触发保护性错误(page fault)，OS 捕捉到这个错误后才会真正复制一份新的物理内存页，然后更新该进程的页表项，让它的虚拟地址指向这个新的物理页，并取消只读标记，另一方则继续使用旧物理页

[Q] 线程的可重入性
[A] 
可重入函数 (Reentrant Function) 指的是一个可以被安全地中断，并在中断处理中被再次调用，而不会破坏第一次调用的数据或状态的函数。

一个函数要成为可重入的，通常必须满足以下条件：
- 不使用（可修改的）全局变量或静态变量：函数不能修改任何存储在自身之外的、生命周期超出本次调用的变量。读取一个常量全局变量是可以的。
- 不返回指向静态变量的指针：返回的地址不能是函数内部一个静态变量的地址，因为下次调用会覆盖它。
- 所有数据都由调用者提供：函数操作所需的所有数据，要么通过函数参数传入，要么在函数内部创建为局部变量（存储在栈上）。
- 不调用非可重入的函数：如果一个函数调用了任何一个非可重入函数，那么它自身也绝不可能是可重入的。

线程安全与可重入性的区别：
- 线程安全 (Thread-Safety)：关注的是多个线程同时访问共享资源时的正确性。它的目标是防止竞态条件 (Race Condition)。通常通过加锁（Mutex）等同步机制来保护共享资源，确保同一时间只有一个线程可以访问。
- 可重入性 (Reentrancy)：关注的是函数被中断并再次调用时的正确性。它的目标是避免因“重入”导致的数据混乱。它通过避免共享状态来实现，而不是通过加锁。

线程安全与可重入性的联系：
- 所有可重入函数都是线程安全的。因为可重入函数不使用共享资源，所以多个线程同时调用它自然不会有任何问题。
- 但一个线程安全的函数不一定是可重入的。

[Q] 判断资源数与死锁的关系
[A] 考虑最坏，最容易导致死锁的情况：就是当每一个进程都已经获得了差一个就能满足其峰值需求的资源数量，然后它们同时去申请那最后一个资源。如果此时系统已经没有剩余资源可供分配，死锁就发生了。我们的目标就是让系统在上述最坏情况下，依然至少还剩一个资源可以分配出去。只要有一个进程能拿到它需要的最后一个资源，它就能执行完毕，然后释放它持有的所有资源，从而打破僵局，让其他进程也能继续执行。

[Q] CPU 进程调度策略
[A] 
|调度算法|抢占式/非抢占式|核心思想|优点|缺点|
|:-|:-:|:-|-|-|
|先来先服务（FCFS, First-Come, First-Served）|非抢占式|按照进程到达的先后顺序进行调度。非常公平，就像排队|实现简单，公平|效率低下。如果一个长作业先到达，后面的一堆短作业就必须长时间等待，导致平均等待时间很长。这就是著名的护航效应 (Convoy Effect)|
|最短作业优先 (SJF, Shortest Job First)|非抢占式|从就绪队列中选择一个估计执行时间最短的进程投入运行|证明可得，在所有进程同时到达的情况下，SJF的平均等待时间和平均周转时间最短，效率最高|对长作业不友好，可能导致长作业永远得不到调度，产生“饥饿 (Starvation)”现象。需要预知进程的执行时间，这在实际中难以精确获得|
|最高响应比优先 (HRRN, Highest Response Ratio Next)|非抢占式|SJF和FCFS的折中。每次调度时，计算所有就绪进程的响应比，选择响应比最高的进程。响应比 R = (等待时间 + 要求服务时间) / 要求服务时间|既考虑了等待时间（照顾老进程），又考虑了执行时间（照顾短进程）。有效地防止了饥饿现象，是比较均衡的算法|计算响应比有额外开销|
|最长剩余时间优先（LRTF，Longest Remaining Time First）|抢占式|在**每一个时间单位** ，调度器都会检查所有就绪队列中的进程，选择那个剩余执行时间最长的进程来运行。因为是可抢占的，所以如果一个正在运行的进程的剩余时间不再是最长的（比如被新来的进程超过，或者它自己运行后时间减少了），它就会被挂起，让位给新的最长者。|
|最短剩余时间优先（SRTF，Shortest Remaining Time First）|抢占式|在**每一个时间单位** ，调度器都会检查所有就绪队列中的进程，选择那个剩余执行时间最短的进程来运行。因为是可抢占的，所以如果一个正在运行的进程的剩余时间不再是最短的，它就会被挂起，让位给新的最短者。|
|优先级调度 (Priority Scheduling)|抢占式/非抢占式|为每个进程分配一个优先级，调度器总是选择优先级最高的就绪进程||可能导致低优先级进程饥饿，解决方案：老化 (Aging) 技术，即进程的优先级随着等待时间的增加而动态提高|
|轮转调度 (RR, Round-Robin)|抢占式|将所有就绪进程按FCFS原则排成一个队列。调度器每次从队头取一个进程，让它运行一个固定的时间片 (Time Quantum)。时间片用完后，若进程未完成，则将其移到队尾，CPU交给下一个进程。|公平，响应时间快，不会产生饥饿。特别适合分时系统。|时间片的设置是关键。太大则退化为FCFS，太小则上下文切换过于频繁，系统开销大。平均周转时间通常较长|
