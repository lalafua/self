[Q] 层级防火墙
[A] 任何一个合格的第 4 层防火墙，都必须首先具备完整的第 3 层处理能力。控制 ICMP 是它在执行其第 3 层功能，而控制特定端口的 TCP/UDP 流量才是它体现其第 4 层高级功能的地方。
- 第 3 层防火墙（或叫包过滤路由器）：它的能力上限就是读取 IP 包头。它可以根据源/目标 IP 地址和协议类型（ICMP, TCP, UDP）来过滤，但它不认识 TCP/UDP 的端口号。
- 第 4 层防火墙：它包含了第 3 层防火墙的所有功能，并且能力得到了扩展。它不仅能看懂 IP 地址和协议类型，还能进一步看懂 TCP/UDP 的端口号。

[Q] 字节流与消息流
[A] 
字节流
1. 字节流将数据视为一个连续不断地，没有边界的字符序列，发送方可分多次写入，接收方可分多次读取，但无法保证发送方每一次 `write` 恰好对应接收方一次 `read` 操作
2. 关键特性：
    - 无边界（No Boundaries）
    - 面向流 (Stream-oriented)：数据是连续的
    - 可靠有序：如TCP会保证所有字节都按发送的顺序到达，并且不会丢失或重复
    - 可能发生粘包或拆包：
        - 粘包（Sticky Packets）: 发送方连续发送两个小数据包（如 "Hello" 和 "World"），接收方可能在一次读取中就收到了 "HelloWorld"
        - 拆包（Packet Splitting）: 发送方发送一个大数据包（如 "HelloWorld"），接收方可能分两次才读完，第一次读到 "Hello"，第二次读到 "World"。
3. TCP (Transmission Control Protocol) 是典型的字节流协议
4. 应用层的责任
    因为TCP本事不提供消息边界，所以如果应用程序需要处理一个个独立的消息，就必须自己定义消息的边界。常见的方法有：
    - 固定长度消息：每个消息都约定为固定长度，比如 256 字节。
    - 使用分隔符：在每个消息的末尾加上一个特殊字符（如 \n），HTTP 协议头就是这么做的。
    - 长度前缀：在每个消息的头部加上一个字段，用来指明该消息的长度。

消息流
1. 消息流将数据视为一个个独立的、有明确边界的数据单元，称为“数据报”(Datagram)。发送方发送的每个数据包都是一个完整的、不可分割的单元
2. 关键特性
    - 有边界 (Boundaries Preserved)：发送方发送的每个数据报，接收方都会作为一个完整的数据报来接收。
    - 面向消息 (Message-oriented)：数据以独立的消息（数据报）为单位进行传输。
    - 不可靠、无序：协议（如UDP）不保证消息一定能到达，也不保证它们的到达顺序与发送顺序一致。消息可能会丢失、重复或乱序。
    - 不会发生粘包或拆包：应用层的数据边界由传输层协议保证。
3. UDP (User Datagram Protocol) 是典型的消息流（或称数据报）协议
4. 应用层的责任
因为 UDP 本身是不可靠的，如果应用程序需要保证消息的可靠性和顺序，就必须自己实现确认、重传和排序等逻辑。

[Q] TCP窗口缩放与带宽时延积（BDP，Bandwidth-Delay Product）
[A]
1. 原始TCP窗口的限制
在标准的TCP头部中，用于流量控制的接收窗口（Receive Window, rwnd）字段只有 16位。
    - 这意味着，一个TCP接收端能通告给发送端的最大缓冲区大小是 2¹⁶ - 1 = 65,535字节（约64 KB）。
    - 根据TCP的流量控制规则，发送方在任何时刻“在途”（已发送但未确认）的数据量不能超过接收方通告的窗口大小。
    - 因此，在没有窗口缩放的情况下，一个TCP连接中最多只能有64 KB的数据在网络中传输。
2. 64KB不够用
在现代网络中，64 KB的窗口大小严重限制了TCP的性能，通过带宽时延积来理解：
    - BDP = 带宽（Bandwidth） x 往返时间（RTT，Round-Trip Time）
    - BDP 的物理意义是：要完全填满网络管道并实现最大吞吐量，需要同时在网络中传输的数据量
3. 解决方案：TCP窗口缩放选项
    - 工作原理：它不是去修改TCP头部的16位窗口字段（因为这会破坏协议的兼容性），而是在TCP的选项（Options）字段中增加了一个新的选项。这个选项只在建立连接的三次握手阶段进行协商
    - 16位窗口字段的真实值：TCP头部中的窗口值 x 2^S （相当于将16位窗口值向左逻辑移位 S 位）
    - 移位因子（S）：8位的数，但最大有效值为 14
4. 效果
最大真实窗口可拓展到：（2^16 - 1）x 2^14 ≈ 2^30 = 1GB

[Q] TCP的选择性确认（Selective Acknowledgment, SACK），Selective Repeat
[A]
1. TCP标准确认机制，Go Back N，累计确认（Cumulative Acknowledgment）
    - 工作方式：接收方发送的ACK号表示“我已经按顺序收到了这个ACK号之前的所有字节，现在我期望收到从这个ACK号开始的数据”
    - 问题所在：当网络中发生多个数据包丢失时，这个机制效率极低，当部分数据包丢失时，会毫无必要的重传所有后续数据包，非常浪费网络带宽
2. SACK如何解决这个问题
    - 核心思想：允许接收方在发送累积确认的同时，额外地、明确地告诉发送方哪些非连续的数据块已经被成功接收
